# The default Window starts at 00:00 UTC of the current day

The spec says the app opens on a Query "from today". If "today" meant the visitor's current instant, every visitor would ask for a different Window and no cached answer would ever be reused, so the first answer would always cost a full engine run (one to four seconds for a Curated Site on the VPS, and competitors take 18 to 40 s). We fix the default Window's start at 00:00 UTC of the current day, with the default duration and Observer height. The backend computes every Curated Site over that Window in a background thread after it starts and again just after each UTC midnight, so the cache serves the whole day. The frontend must send that exact start in the default Query; any other start is still answered, only not from the warmed cache. Visitors east or west of Greenwich see a Window that began a few hours before or after their local midnight, which we accept for a Window about a month long.
